# Demo clips

Six short RAVDESS excerpts, one per emotion in the acoustic branch's reach plus the
two it cannot express. They exist so that the interface has something to analyse on
a machine with no dataset, and so that a demonstration can use real speech with a
known ground-truth label instead of a tone.

| File | Ground truth | Why it is here |
|---|---|---|
| `ravdESS_neutral_*.wav` | neutral | baseline; low arousal, low lexical affect |
| `ravdESS_happy_*.wav` | happy | high arousal, positive valence |
| `ravdESS_sad_*.wav` | sad | low arousal, negative valence |
| `ravdESS_angry_*.wav` | angry | the acoustic head's strongest class |
| `ravdESS_fearful_*.wav` | fearful | **outside** the acoustic vocabulary — coverage is visible here |
| `ravdESS_disgust_*.wav` | disgust | also outside the acoustic vocabulary |

The two italicised rows are the interesting ones for a demonstration: the acoustic
branch cannot emit `fear` or `disgust`, so its projection leaves mass unexpressed and
the fused result leans on the text branch. That is the mechanism working as designed,
not a bug.

## What is in the files

- Mono, 16 kHz, 16-bit PCM — the rate the pipeline resamples to anyway.
- Silence-trimmed and capped at 4 s, so all six total well under 1 MB.
- Ground truth is encoded in the RAVDESS filename, not inferred.

## Regenerating

```bash
python scripts/fetch_ravdess.py --from-zip data/raw/Audio_Speech_Actors_01-24.zip
```

The script takes the first archive member for each emotion code, then downmixes,
resamples, trims and caps it. It writes the provenance file alongside the audio.

## `probes/`

`demo_samples/probes/` holds six **synthetic** two-second signals (tones, not speech)
that exercise the decoder, the prosody extractor and the SNR estimate without any
dataset. They are generated by `scripts/prepare_demo_samples.py`, are excluded from
version control, and are never shown as interface examples — interpreting emotion
from them would be meaningless by construction.
